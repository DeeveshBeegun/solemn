# Solemn incident runbooks

All commands operate on the configured forward account. Use `FORWARD_MARKET_DATA_MODE` and, for replay, `FORWARD_ACCOUNT` to select the intended portfolio. Start with `pnpm solemn:health`, `pnpm solemn:incidents` and `pnpm solemn:reconcile`. A reconciliation command reads evidence and reports mismatches without changing records.

| Incident                          | Symptoms and immediate action                                                                                                                                         | Diagnosis and recovery                                                                                                                                                                             | Escalation                                                                       |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Market-data disconnect            | Feed disconnected or gap observed. Expect `DEGRADED` unless an administrative hold already applies. Preserve positions and let the worker invalidate pending entries. | Check connection, message and gap fields in `solemn:health`. Restore transport and confirm valid observations, complete indicators and executable quotes before entry readiness returns.           | Repeated gaps, missing coverage or an unpriced holding that cannot be monitored. |
| Prolonged stale prices            | Last valid observation exceeds the configured age. Expect `DEGRADED` and uncertain equity.                                                                            | Check provider clocks and observation provenance. Compare trade and quote timestamps and restore verified pricing. Use `paper:positions` to inspect unresolved exposure.                           | Position lacks a reliable market or recoverable executable depth.                |
| Provider API outage               | Timeouts, rate-limit counters or unavailable quote. Stop optional quote traffic during recovery.                                                                      | Check provider diagnostics and documented cooldown. Re-establish fresh risk and execution evidence before considering new orders.                                                                  | Sustained quota failure or discrepancies between independent sources.            |
| Database connection failure       | Health reports `FAILED`, or the owner disconnects. Stop the affected worker if it has not exited and retain local logs.                                               | Verify PostgreSQL connectivity and migration compatibility. Restart and run reconciliation. Expect an unclean session to remain `HALTED` once the database is reachable.                           | Unknown commit outcome, persistent writes failing, or lost ledger evidence.      |
| Portfolio reconciliation mismatch | Reconciliation fails or startup records a ledger incident. Halt with a documented incident reason and preserve logs and database evidence.                            | Compare journal hashes, materialized order and fill records, and backups in a separate copy. Recovery requires a validated ledger and operator approval.                                           | Any unexplained posting, balance or quantity. Preserve evidence before repair.   |
| Blocked paper exit                | Open position reports `EXIT_BLOCKED` or valuation uncertainty. Keep it recorded and stop new entries.                                                                 | Inspect `paper:positions`, execution observations, fees and reserve state. Resume protective attempts only with supported fresh execution data.                                                    | Liquidity remains unavailable or the fill outcome cannot be reconstructed.       |
| Duplicate worker                  | Advisory lock conflict and possible `HALTED` incident. Stop the duplicate process.                                                                                    | Confirm one intended database session, inspect `solemn:status` and reconcile. Restart the intended worker and verify ownership before reset.                                                       | Active writer lacks the expected lock or session ownership changes unexpectedly. |
| Daily loss limit                  | Ledger shows `DAILY_LOSS_LIMIT`; reliable forward breach latches `HALTED`. Keep monitoring exits.                                                                     | Review UTC day baseline, realized P&L and marked equity. Confirm the daily constraint is cleared and follow the reset procedure.                                                                   | Equity is uncertain or a limit triggers with unexplained cash movement.          |
| Maximum drawdown                  | Ledger records `TOTAL_DRAWDOWN_LIMIT` and new entries stop. Preserve equity and peak evidence.                                                                        | Review the latest reliable marks and equity peak. The explicit ledger reset can establish a new baseline, so archive the prior evidence and record the justification.                              | Unreliable mark, unexplained peak or unresolved exposure.                        |
| Emergency halt and recovery       | Run `pnpm solemn:halt --reason "Incident reference"` and verify `HALTED` plus closed entry gate. Existing positions remain tracked.                                   | Address the cause, reconcile, establish a healthy owned worker and confirm resolved exposures. Run `pnpm solemn:reset-halt --reason "Incident verified"` and verify `RECOVERING` before `RUNNING`. | Missing evidence, stale health, unknown ownership or a failed reset.             |
| Suspected credential exposure     | Stop affected services and keep credential values out of incident text.                                                                                               | Revoke and rotate the credentials, review access logs and restore trusted configuration. Reconcile and verify provider access before resuming.                                                     | Evidence of unauthorized access or an unknown period of exposure.                |
| Unexpected submission capability  | Stop the worker and isolate provider credentials and outbound access.                                                                                                 | Inspect the running build, dependency imports, endpoint configuration and deployment provenance. Preserve evidence and resume only with a reviewed paper-only build.                               | Any indication of signing, broadcast, or on-chain balance movement.              |

## Release acceptance

Run the offline release gate and retain its JSON summary before updating an operator-managed deployment. Keep the current portfolio and prior configuration backed up. For a failed migration, a startup compatibility error or an unexplained ledger mismatch, keep the writer stopped and follow the [release rollback procedure](release-rollback.md). The [readiness decision](../release/release-readiness.md) defines the restricted candidate scope.
